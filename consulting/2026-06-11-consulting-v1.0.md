## 1. 분석 배경

이전 UI/UX 개선 사이클(handover/test-report-v2-fixed.md)에서 Critical/High 버그는 모두 해결됐으나,
Medium 등급 이슈 #M1~#M5가 "차기 마일스톤 권장"으로 미해결 상태로 남았다.
본 사이클은 해당 잔여 이슈를 사용자 관점에서 재평가하고, 코드 재분석 중 발견한 신규 이슈 1건을 추가하여
**"오류·빈 상태 UX 개선"**을 주제로 진행한다.

## 2. 사용자 관점 문제 분석

### P1. 네트워크 오류 시 완전한 침묵 (심각도: 높음) [기존 #M5]
- **현상**: 홈/탐색 탭에서 카테고리·방송 목록 로드가 실패하면 화면이 그냥 비어있다.
  오류 안내도, 재시도 수단도 없다. 사용자는 앱이 고장났는지 네트워크 문제인지 알 수 없다.
- **근거 코드**:
  - `HomeViewController.swift:108-117` — `fetchCategories`가 `if case .success`만 처리. 실패 시 무동작.
  - `ExploreViewController.swift:74-88` — 동일 패턴.
- **사용자 영향**: TV 앱 특성상 일시적 네트워크 끊김이 잦은데, 복구 수단이 앱 재시작뿐.

### P2. 검색 탭 영구 데드락 (심각도: 높음) [신규 발견]
- **현상**: 검색 풀 로드(`loadAllBroadcasts`)의 `fetchCategories`가 실패하면
  `guard ... case .success else { return }`으로 조용히 종료되고 `hasLoadedAll`이 영원히 false로 남는다.
  이후 사용자가 무엇을 검색해도 "방송 목록을 불러오는 중" 토스트만 반복되고 **재로드 트리거가 없다**.
- **근거 코드**: `SearchViewController.swift:146-169` (`hasLoadedAll`은 Play/Pause 리모컨 새로고침 외에 복구 경로 없음).
- **사용자 영향**: 검색 기능 자체가 영구 불능. 사용자는 원인을 알 수 없음.

### P3. MY 탭 오류 메시지에 개발자 용어 노출 (심각도: 중간)
- **현상**: 즐겨찾기 로드 실패 시 `"로드 실패: \(err)\n\n로그인이 안 됐을 수 있습니다.\n(.env의 SOOP_ID/PASSWORD 확인)"`
  — 원시 에러 객체와 `.env` 같은 개발자 전용 용어가 TV 화면에 그대로 노출된다.
- **근거 코드**: `MyViewController.swift:125`.
- **사용자 영향**: 신뢰도 하락, 조치 불가능한 안내. 재시도 수단도 없음.

### P4. 브랜드 워드마크 가림 위험 (심각도: 낮음) [기존 #M1]
- **현상**: `RootTabBarController`의 "SOOP" 워드마크가 `addSubview` 후
  `bringSubviewToFront` 없이 방치되어, viewControllers 콘텐츠에 가려질 수 있다.
- **근거 코드**: `RootTabBarController.swift:92-99`.

### P5. 홈 스켈레톤 위에서 reloadData (심각도: 낮음) [기존 #M2]
- **현상**: 카테고리 데이터가 먼저 도착해 스켈레톤이 떠 있는 동안 테이블이 reload되고,
  스켈레톤은 인기 라이브 머지가 끝나야 사라진다. 실패 시 타임아웃까지 스켈레톤이 유지된다.
- **근거 코드**: `HomeViewController.swift:85-105, 135-139`.

### P6. 검색 범위 미안내 (심각도: 낮음) [기존 #M3 잔여]
- **현상**: 검색 풀이 상위 15개 카테고리로 제한되는데 사용자에게 알리지 않는다.
  결과 0건일 때 "결과가 없습니다"만 떠서, 실제로는 검색 범위 밖일 수 있음을 알 수 없다.
- **근거 코드**: `SearchViewController.swift:154, 229-231`.

### P7. 검색 emptyLabel·결과 그리드 겹침 (심각도: 낮음) [기존 #M4]
- **현상**: `emptyLabel`이 `resultsCollectionView`와 같은 영역에 배치되어 토글 타이밍에 따라 겹쳐 보일 수 있다.
- **근거 코드**: `SearchViewController.swift:111-134`.

## 5. 진행 프로세스

1. 기획 에이전트 → 개선 항목별 상세 기획 (consulting/ 폴더에 기획서 저장)
2. 디자인 에이전트 → 오류 상태 뷰 등 디자인 명세 (consulting/ 폴더에 디자인서 저장)
3. 코딩 에이전트 (**Fable 모델**) → 구현 + 빌드 검증
4. 검수 에이전트 → 체크 포인트 채점 (inspection/ 폴더, 100점까지 검수↔코딩 반복)
5. 테스트 에이전트 → 가상 테스트 시나리오 채점 (100점까지 테스트↔코딩 반복)
6. handover/ 폴더에 최종 요약 + 추가 확인 필요 사항 정리
