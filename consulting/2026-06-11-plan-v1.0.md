## 1. 개선 항목 I-1: 홈/탐색 데이터 로드 실패 시 오류 상태 뷰 + 재시도

### 1-1. 사용자 시나리오

**As-Is**  
홈(HOME) 또는 탐색(탐색) 탭에서 카테고리 로드가 실패하면 화면이 그냥 비어있다.  
스켈레톤은 1.5초 timeout 후 사라지고 아무 콘텐츠도 표시되지 않는다.  
사용자는 앱이 멈춘 건지, 네트워크 문제인지 알 수 없다.

**To-Be**  
로드 실패가 확정되면 스켈레톤이 즉시 사라지고, 화면 중앙에 오류 상태 뷰가 나타난다.  
오류 상태 뷰에는 아이콘, 한 줄 안내 문구, "다시 시도" 버튼이 포함된다.  
버튼을 선택하면 즉시 재로드를 시도하고, 버튼이 사라지며 스켈레톤이 다시 표시된다.  
재로드 성공 시 스켈레톤이 사라지고 정상 화면이 나타난다.

### 1-2. 기능 요구사항

**오류 상태 뷰 구성 요소 (화면 중앙 수직 배치)**
- SF Symbol 아이콘: `wifi.exclamationmark` (tintColor: `DS.Colors.textTertiary`, 크기 80×80)
- 안내 문구 (1줄): `DS.Typography.subsection`, `DS.Colors.textSecondary`
- "다시 시도" 버튼: `UIButton.Configuration.filled()` 사용, `DS.Colors.primary` 배경, `DS.ButtonInsets.cta` 인셋, `DS.Corner.button` 반경

**포커스 동작**
- 오류 상태 뷰가 나타나면 포커스는 즉시 "다시 시도" 버튼으로 이동한다.
- 버튼은 `canBecomeFocused = true`이어야 하며, 포커스 시 `FocusEffect.applyBorder(to:focused:)` 적용.
- Play/Pause 리모컨 버튼 동작은 기존과 동일하게 유지 (재로드 + 토스트).

**홈(HomeViewController) 적용 범위**
- `fetchCategories` 실패 시: 오류 상태 뷰 표시
- `loadPopularLive` 전체 실패 시 (3개 카테고리 fetchBroadcasts 전부 실패): 오류 상태 뷰를 유지하거나, 카테고리만 성공했다면 카테고리 섹션은 표시하고 인기 라이브 섹션만 비운다.
- 재시도 시 `loadData()` 전체를 다시 호출한다.

**탐색(ExploreViewController) 적용 범위**
- `fetchCategories` 실패 시: 오류 상태 뷰 표시 (검색 진입 셀 SearchEntryCell은 항상 표시 유지)
- 재시도 시 `loadData()` 전체를 다시 호출한다.

### 1-3. 상태 전이

```
[진입] → [로딩: 스켈레톤 표시] → {fetchCategories 결과}
    ├─ .success → [스켈레톤 즉시 해제] → [콘텐츠 표시]
    │               └─ loadPopularLive 병렬 수행
    │                   ├─ 하나라도 성공 → [인기 라이브 섹션 채움]
    │                   └─ 전부 실패 → [인기 라이브 섹션 비움, 나머지 유지]
    └─ .failure → [스켈레톤 즉시 해제] → [오류 상태 뷰 표시, 버튼 포커스]
                    └─ "다시 시도" 선택 → [오류 상태 뷰 숨김] → [스켈레톤 표시] → 처음부터 반복
```

### 1-4. 확정 문구

| 상황 | 표시 문구 |
|------|---------|
| 홈 카테고리 로드 실패 | "콘텐츠를 불러오지 못했습니다" |
| 탐색 카테고리 로드 실패 | "콘텐츠를 불러오지 못했습니다" |
| 재시도 버튼 | "다시 시도" |
| Play/Pause 새로고침 토스트 (기존 유지) | "새로고침 중..." |

### 1-5. 엣지 케이스

| 케이스 | 처리 방식 |
|--------|---------|
| "다시 시도" 연타 (빠른 반복 선택) | 첫 번째 선택 시 버튼을 `isEnabled = false`로 비활성화. 로드 완료(성공/실패) 후 재활성화 또는 오류 뷰 재표시. |
| 탭 전환 중 응답 도착 | `guard let self` + `DispatchQueue.main.async` 패턴 유지. 탭이 백그라운드여도 UI 반영 — 탭 복귀 시 정상 표시. |
| 카테고리 성공, 인기 라이브 전부 실패 | 오류 상태 뷰를 띄우지 않음. 인기 라이브 섹션만 비운다(기존 동작). |
| 네트워크 복구 후 Play/Pause | `loadData()` 재호출 → 기존 로직 그대로. 별도 처리 불필요. |

### 1-6. 영향 파일

| `HomeViewController.swift:85-105` | `showSkeleton()` — hideSkeleton 호출 시점 변경 (I-5와 연계) |
| `ExploreViewController.swift:74-88` | `loadData()` — 실패 분기 추가 |

## 2. 개선 항목 I-2: 검색 풀 로드 실패 복구

### 2-1. 사용자 시나리오

**As-Is**  
검색 화면 진입 시 `loadAllBroadcasts()`가 실행된다.  
`fetchCategories`가 실패하면 `guard ... case .success else { return }`으로 함수가 종료되고  
`hasLoadedAll`은 영원히 `false`로 남는다.  
이후 사용자가 무엇을 검색해도 "데이터 준비 중입니다. 잠시 후 다시 시도해 주세요" 토스트만 반복된다.  
Play/Pause 새로고침 버튼은 `reloadPool()`을 호출하지만, 이미 동일 코드 경로를 타므로 동일하게 실패한다.  
**복구 불가 상태.**

**To-Be**  
`loadAllBroadcasts()`가 실패하면 `hasLoadedFailed = true` 상태를 기록한다.  
사용자가 다음 검색 시도(`updateSearchResults` 또는 `runSearch` 호출) 시,  
`hasLoadedAll == false && hasLoadedFailed == true` 조건을 감지해 자동으로 `loadAllBroadcasts()`를 재시도한다.  
재시도 중임을 토스트로 안내하고, 성공 시 검색을 이어서 실행한다.

### 2-2. 기능 요구사항

**`SearchResultsViewController` 상태 변수 추가**
- 기존: `private var hasLoadedAll = false`
- 추가: `private var hasLoadFailed = false`

**`loadAllBroadcasts()` 실패 처리**
- `fetchCategories` 실패(`case .failure` 또는 guard 탈락) 시 → `hasLoadFailed = true`로 기록
- `hasLoadedAll`은 여전히 `false`로 유지

**`runSearch(_:)` 진입부 로직 변경**
- 현재: `if !hasLoadedAll { ToastView.show(...); return }`
- 변경 후:
  - `hasLoadedAll == false && hasLoadFailed == false` → "데이터 준비 중" 토스트 (기존)
  - `hasLoadedAll == false && hasLoadFailed == true` → 자동 재시도 토스트 + `loadAllBroadcasts()` 재호출. 재시도 중에는 재진입 방지 (`isReloading` 플래그).
  - `hasLoadedAll == true` → 정상 검색

**재시도 중 중복 검색 방지**
- `isReloading = true` 상태에서 또 검색 시도 → "데이터를 다시 불러오고 있습니다" 토스트만 표시하고 재시도 추가 실행 없음.

**재시도 성공 후 처리**
- `hasLoadedAll = true`, `hasLoadFailed = false`, `isReloading = false`
- 마지막으로 시도한 검색어(`pendingQuery`)로 즉시 검색 실행

### 2-3. 상태 전이

```
[초기] hasLoadedAll=false, hasLoadFailed=false, isReloading=false

loadAllBroadcasts() 호출
    ├─ fetchCategories 성공 + fetchBroadcasts 완료 → hasLoadedAll=true
    └─ fetchCategories 실패 → hasLoadFailed=true

[사용자 검색]
    hasLoadedAll=true → 정상 필터링 실행
    hasLoadedAll=false, hasLoadFailed=false → "데이터 준비 중" 토스트
    hasLoadedAll=false, hasLoadFailed=true, isReloading=false
        → "검색 데이터를 다시 불러옵니다" 토스트 + loadAllBroadcasts() 재실행
            ├─ 성공 → hasLoadedAll=true, isReloading=false → pendingQuery로 검색 실행
            └─ 실패 → hasLoadFailed=true, isReloading=false (다음 검색 시 다시 재시도)
    hasLoadedAll=false, isReloading=true → "데이터를 다시 불러오고 있습니다" 토스트
```

### 2-4. 확정 문구

| 상황 | 표시 문구 |
|------|---------|
| 초기 로딩 중 검색 시도 | "데이터 준비 중입니다. 잠시 후 다시 시도해 주세요" (기존 유지) |
| 실패 후 자동 재시도 | "검색 데이터를 다시 불러옵니다" |
| 재시도 중 재검색 시도 | "데이터를 다시 불러오고 있습니다" |
| Play/Pause 새로고침 토스트 (기존 유지) | "검색 풀 새로고침 중..." |

### 2-5. 엣지 케이스

| 케이스 | 처리 방식 |
|--------|---------|
| 재시도 실패 반복 | 매 검색 시도마다 재시도. 무한 루프 위험 없음 (사용자가 능동적으로 검색해야 트리거됨). |
| Play/Pause 새로고침 | 기존 `reloadPool()`이 `hasLoadedAll = false`를 먼저 리셋 후 `loadAllBroadcasts()` 재호출. 실패 상태도 같이 초기화해야 하므로 `hasLoadFailed = false`, `isReloading = false`도 함께 리셋. |
| 카테고리는 성공, fetchBroadcasts 전체 실패 | `hasLoadedAll = true`로 간주 (빈 풀). 검색 결과 0건 → I-6 범위 안내로 처리. |

## 3. 개선 항목 I-3: MY 탭 오류 메시지 사용자 친화화 + 재시도

### 3-1. 사용자 시나리오

**As-Is**  
즐겨찾기 로드 실패 시 화면 중앙의 `statusLabel`에 아래 문구가 그대로 출력된다.

```
로드 실패: The operation couldn't be completed. (SOOPAPIError.loginRequired)

로그인이 안 됐을 수 있습니다.
(.env의 SOOP_ID/PASSWORD 확인)
```

원시 에러 객체(`\(err)`)와 `.env`, `SOOP_ID/PASSWORD` 같은 개발자 전용 용어가 TV 화면에 노출된다.  
재시도 수단도 없다.

**To-Be**  
실패 시 `statusLabel`을 숨기고, 아이콘 + 사용자 친화 문구 + "다시 시도" 버튼으로 구성된 오류 상태 뷰를 표시한다.  
오류 유형에 따라 문구가 다르게 표시된다.

### 3-2. 기능 요구사항

**`loadFavorites()` 실패 분기 변경**
- 기존: `statusLabel.text = "로드 실패: \(err)\n\n로그인이 안 됐을 수 있습니다.\n(.env의 SOOP_ID/PASSWORD 확인)"`
- 변경 후: `statusLabel.isHidden = true` + `showErrorState(for: err)` 호출

**오류 상태 뷰 구성** (`showErrorState` 메서드 신설)
- SF Symbol 아이콘: `person.crop.circle.badge.exclamationmark` (tintColor: `DS.Colors.textTertiary`, 크기 80×80)
- 오류 안내 문구 (1줄): 에러 유형별 분기 (아래 표 참조)
- 보조 문구 (1줄, 선택): 조치 방법 안내
- "다시 시도" 버튼: `DS.Colors.primary`, `DS.ButtonInsets.cta`, `DS.Corner.button`
- 기존 `showEmptyState()` 구조를 그대로 참조하여 구현 (아이콘/문구만 교체)

**포커스 동작**
- 오류 상태 뷰 표시 즉시 "다시 시도" 버튼에 포커스 이동
- 버튼 선택 → `loadFavorites()` 재호출 → 오류 상태 뷰 해제 + statusLabel "즐겨찾기 불러오는 중..." 표시

**오류 상태 뷰 숨김 시점**
- `loadFavorites()` 호출 시 즉시 (`hideEmptyState()`처럼 `hideErrorState()` 호출)

### 3-3. 에러 유형별 문구 분기

| 에러 케이스 | 안내 문구 | 보조 문구 |
|------------|---------|---------|
| `SOOPAPIError.loginRequired` 또는 인증 관련 | "로그인 정보를 확인할 수 없습니다" | "SOOP 계정으로 로그인되어 있는지 확인해 주세요" |
| 그 외 네트워크/서버 오류 | "즐겨찾기를 불러오지 못했습니다" | "인터넷 연결을 확인하고 다시 시도해 주세요" |

*주의: `SOOPAPIError` 케이스 목록은 `SOOPAPIClient.swift`에서 확인. 기획서 확정 문구가 최우선. 개발자 용어 절대 금지.*

### 3-4. 상태 전이

```
[진입] loadFavorites() 호출
    └─ statusLabel 표시("즐겨찾기 불러오는 중..."), 오류 상태 뷰 숨김

fetchFavorites 결과
    ├─ .success(빈 배열) → statusLabel 숨김 → showEmptyState() (기존 빈 상태 그대로)
    ├─ .success(데이터 있음) → statusLabel 숨김 → 그리드 표시 (기존 그대로)
    └─ .failure → statusLabel 숨김 → showErrorState(오류 유형별 문구 + 재시도 버튼)
                    └─ "다시 시도" 선택 → [위로 돌아감]
```

### 3-5. 확정 문구

| 상황 | 표시 문구 |
|------|---------|

## 5. 개선 항목 I-5: 홈 스켈레톤 해제 타이밍 정리

### 5-1. 사용자 시나리오

**As-Is**

**To-Be**  
`fetchCategories` 결과(성공/실패)가 확정되는 즉시 스켈레톤을 해제한다.

### 5-2. 기능 요구사항

## 8. tvOS 플랫폼 제약 고려사항

### 8-1. 포커스 엔진
- tvOS에서는 터치가 없다. 모든 상호작용은 Siri Remote의 방향키 + Select(선택) + Play/Pause + Back 버튼으로 이루어진다.
- 오류 상태 뷰의 "다시 시도" 버튼은 반드시 `canBecomeFocused = true`이어야 한다.
- 오류 상태 뷰 표시 즉시 `setNeedsFocusUpdate()` + `updateFocusIfNeeded()`를 호출해 포커스를 "다시 시도" 버튼으로 이동시킨다.
- `preferredFocusView`를 오버라이드하거나 `UIFocusGuide`를 활용할 수 있다. MY 탭의 `showEmptyState()` 패턴 참조.

### 8-2. 화면 해상도 및 safe area
- 1920×1080, TV UI 가이드라인상 좌우 60~90pt, 상하 60pt 이상의 여백 권장.
- 오류 상태 뷰는 기존 `MyViewController.showEmptyState()`처럼 `centerX/centerY` + `widthAnchor ≤ 720`으로 배치한다.

### 8-3. 3미터 시청 거리 가독성
- 오류 안내 문구: `DS.Typography.subsection` (28pt semibold) 이상 사용.
- 보조 문구: `DS.Typography.body` (20pt regular) 이상 사용.
- 개발자 용어, 기술 스택 용어, URL, 에러 코드는 절대 노출 금지.

### 8-4. 애니메이션
- 오류 상태 뷰 등장: 별도 애니메이션 없이 즉시 표시 (스켈레톤 해제와 타이밍이 겹치므로 단순 처리).
- 오류 상태 뷰 해제 후 스켈레톤 표시: `showSkeleton()` 기존 코드 그대로 사용.

## 10. 비범위 (Out of Scope)

이번 사이클에서 구현하지 않는 항목을 명시한다.

1. 검색 화면의 전체 카테고리 범위 확장 (현재 15개 → 전체): API 호출 비용 증가, 별도 사이클에서 결정.
2. MY 탭에서 직접 SOOP 즐겨찾기 추가/관리: 별도 인증 플로우 필요.
3. 홈/탐색 부분 실패(카테고리 성공, 인기 라이브 일부 실패) 시 섹션별 오류 표시: 이번 사이클은 전체 실패 시 화면 레벨 오류 뷰만 다룸.
4. 오류 상태 전용 신규 컴포넌트(재사용 가능 `ErrorStateView` 클래스) 설계: 코딩 에이전트가 MY 탭 `showEmptyState()` 인라인 패턴을 그대로 따르면 충분. 추상화 여부는 코딩 에이전트 재량.
5. 탭 간 오류 상태 공유/동기화: 각 화면이 독립적으로 상태를 관리한다.
6. 오프라인 모드 캐시 표시: 네트워크 없을 때 이전 데이터 보여주기.
7. 오류 발생 횟수 기반 지수 백오프(exponential backoff): 단순 수동 재시도로 충분.
8. 검색 탭에서 탭 진입 시 자동 재로드 (탭 전환 이벤트 구독): I-2의 "검색 시도 시 자동 재로드"로 충분.
