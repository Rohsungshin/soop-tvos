## 1. 분석

### 1-0. 방법

추측 대신 실제 데이터로 원인을 확정했다. 모든 하니스는 **앱 소스 파일을 수정 없이 그대로 컴파일**해 썼다.

| 도구 | 용도 |
|------|------|
| 캡처 하니스(macOS CLI) | 앱의 `SOOPNativeReceiver`로 공개 방송(grade 0·비번 없음·구독 전용 아님)에 접속해 0xc748 패킷을 도착 시각과 함께 저장. 본문 전체(3개 방송 × 120초, 1개 × 40초) / 헤더만(16개 × 60초, 4개 × 15분) |
| 리플레이 | 저장본을 `TSMuxer`에 다시 흘려 세그를 만듦(네트워크 없음, 수정 전후 동일 입력) |
| 분석 스크립트 | 패킷 타이밍·cts·오디오 묶음·시퀀스, ffprobe로 세그 PTS/DTS, 원본 대비 PTS 일치 검사 |
| 프로토콜 프로브 | 제어 패킷까지 기록(keep-alive 변형 실험) |
| tvOS 시뮬레이터 하니스 | 먹서+루프백 서버+AVPlayer(**isMuted = true**). 저장본 리플레이 또는 실서버 |
| 실제 앱 검증 빌드 | `/tmp` 복사본에만 임시 훅(방송 지정 실행·음량 0·장애 주입). 작업 트리에는 넣지 않음 |

참조 구현(PERISU21/SOOPTV-1080p, 라이선스 없음)은 **사실 확인용으로만** 읽었다(코드 미복제).

### 1-2. 증상 3-①: 먹서가 오디오의 약 25%를 버림

| 방송 | 입력 오디오 프레임 | 수정 전 출력 | 비율 |
|------|------------------|-------------|------|
| A (48k) | 5,789 | 4,285 | 74.0% |
| B (48k, B-frame) | 5,760 | 4,344 | 75.4% |
| C (44.1k) | 5,297 | 3,941 | 74.4% |

- 오디오 묶음은 묶음이 끝난 뒤 보내져 같은 시각 영상보다 **중앙값 0.47초 늦게** 도착(16개 중 13개 0.41~0.49초, 3개는 반대로 0~0.53초 이름).
- 수정 전 `flushAudioUpTo`는 "세그 첫 영상보다 이른 오디오는 버린다"는 규칙(이전 사이클이 **첫 세그** -12976 때문에 넣음)을 **모든 세그에** 적용했다. IDR(2초마다)에서 세그를 바로 닫으므로 경계 직전 묶음이 경계 뒤에 도착하면 갈 곳이 없어 폐기 → **2초마다 약 0.5초 오디오 구멍**.
- 세그별 실측(방송 B, 수정 전): 영상 2.103~4.085초인데 오디오 2.457~3.972초, 다음 세그와 사이 0.53초 공백이 56회.
- 키프레임 간격이 1초인 방송이면 경계마다 묶음이 거의 다 경계를 넘어 도착해 **오디오가 사실상 나오지 않을 수 있다**.

### 1-3. 증상 1-①·2-①: cts 1/10 환산 + B-frame PTS 접두

- 서버 패킷의 cts(@57, int32)는 dts와 같은 **100ns 단위**다(참조 구현 `cts / 10_000` = ms). 수정 전 코드는 `Int64(cts) * 9 / 10_000` — 정답 `* 9 / 1000`의 1/10.
  - 실측: cts 33ms 프레임의 출력 PTS−DTS가 296틱(3.3ms). 정답 2,970틱. 방송 B 7,266프레임 전부 불일치.
  - 공개 방송 16개 중 **6개가 B-frame**(전 프레임 cts 16~66ms). 이 방송들에서 영상이 오디오보다 최대 수십 ms 먼저, 표시 순서가 뒤섞인 채 나간다 → "일부 방송에서 싱크가 안 맞는다"와 일치.
- 더 큰 문제: B-frame 프레임은 PES에 PTS+DTS를 함께 싣는데, PTS 앞 4비트를 PTS만 실을 때의 `0010`으로 썼다. ISO 13818-1 2.4.3.7은 PTS_DTS_flags='11'이면 PTS `0011` + DTS `0001`이다. ffmpeg는 이 비트를 보지 않아 이전 사이클 검증을 통과했지만 **Apple mpeg2parser는 첫 세그에서 -12976으로 거부**했다.
  - 시뮬레이터(무음) 리플레이: 방송 B — 수정 전 3.8초에 `status=failed -12976`, cts만 고친 판도 동일 실패, **접두 수정 후 1920x1080 재생**.
  - 앱에서는 이 실패가 곧바로 CDN 전환이 된다 → 메뉴가 자동/540p/360p. §4-4에서 실제 앱으로 재현.

### 1-4. 증상 1-②: B-frame 없는 방송도 첫 세그 -12976

방송 D(B-frame 없음, 키프레임 4.17초)는 수정 전 코드로 실서버·리플레이 모두 시작 시 -12976. 원인 분리(같은 40초 캡처 리플레이, 시뮬레이터 무음):

| 변형 | 결과 |
|------|------|
| 수정 전 그대로 | 실패 -12976 |
| 수정 전 + 원점 1초 수정만 | 실패 |
| 수정 전 + 오디오 PCR 제거만 | 실패 |
| **새 세그 조립** + 수정 전 루프백 서버 | **재생** |

수정 전 첫 세그는 오디오 PES마다 **이미 0.45초 더 뒤의 영상 다음에** 놓여 있었다(도착 순서 배치). 새 조립은 시각순(오차 −0.04초). Apple이 정확히 어떤 조건으로 거부하는지까지는 특정하지 못했지만, 결함 변수는 세그 조립 하나로 좁혀졌다.

### 1-5. 증상 3-②: BJ 송출 재시작 → 영구 정지·무음

15분 헤더 캡처 4개 중 1개(방송 E)에서 403.7초에 실제로 발생:

| | 재시작 전 마지막 | 재시작 후 첫 |
|---|---|---|
| 도착 | 396.97초 | 403.72초 (6.75초 공백) |
| 영상 seq / 프레임 번호 | 170,676 / 176,232 | 55 / 59 |
| dts | 2,844.766초 | 2.300초 |
| 형식 | 1080p60, 오디오 48kHz | 720p30, 오디오 44.1kHz |

- 수정 전 먹서는 "시퀀스가 이전보다 커야 받는다" → 이후 영상·오디오를 **전부 중복으로 폐기**(오디오는 46분, 영상은 사실상 영원히). 수신은 계속돼 16초 무수신 폴백도 걸리지 않는다 → **화면 정지 + 음원이 다시 나오지 않음**.
- 같은 데이터 형태를 합성(48k 방송 60초 → 6.75초 공백 → 44.1k 방송, 시퀀스·dts 역행)해 시뮬레이터에서 재현: 수정 전은 60초 지점에서 **영구 정지**(t=61.5에서 rate 0), §4-3.
- 재시작 뒤에도 서버는 구 번호 keep-alive를 문제없이 받아 줬다(공백 2.7초 주기 유지) → 수신기 프레임 번호는 건드리지 않았다.

### 1-6. 증상 1-③: 조용한 CDN 전환·플레이어 중복·메모리 누적

| 위치 | 결함 |
|------|------|
| `observePlaybackFailure` | 루프백 item이 재생 중 실패하면 `tryFallback` → CDN URL로 **토스트 없이** 교체. 네이티브 수신기·루프백 서버는 **멈추지 않고 계속 수신** |
| `fallbackToCDN` | 기존 루프백 `AVPlayerViewController`를 정리하지 않고 CDN 플레이어를 하나 더 붙임. 실제 앱 재현: `avChildren=2` (§4-4) |
| 네이티브 실패 처리 | 재생 중 한 번 끊기면(망 순단 등) 그 방송은 끝까지 CDN(540p) |
| `playLoopbackHLS` | `didRevealPlayer`를 초기화하지 않아, 한 번 드러난 뒤 다시 들어온 네이티브 플레이어는 영영 드러나지 않음(재연결·다시 시도 경로) |
| `LocalHLSServer.append` | `playlist.segments`를 6개로 자르는 루프가 뒤에 있어 `count > maxKept(12)` 분기가 **한 번도 실행되지 않음** → 세그 dict가 재생 내내 누적(1080p60 ≈ 1MB/s) |

### 1-7. 증상 3-③: 서버가 32초마다 송신을 멈춤

- 캡처 19개 **전부** 접속 약 29.5초 뒤 2.3~2.6초 공백, 이후 32초마다 반복. 리드(미디어 시각−도착 시각)는 3.34초로 일정하다가 공백 뒤 재전송으로 따라잡음 — **유실은 없고 지연 후 몰아서 옴**.
- 프로브 결과: 서버는 송신을 (재)시작할 때마다 약 32초 분량(약 2,000프레임)만 보낸다. keep-alive(type 6, 프레임 F)는 "F부터 다시 보내라"(시크)로 동작하며 **송신 중 받은 keep-alive는 창을 늘리지 못하고**, 멈춘 뒤 받은 keep-alive가 다음 창을 연다.

| 실험(각 70~100초) | 결과 |
|------|------|
| 4초 주기(기존) | 32초마다 공백 2.4~2.6초 |
| 2초 주기 | 창은 그대로, 공백 1.0초 |

- 영향: 세그 공백 4.2초 > 1.5×TD(3초) → AVPlayer `-12888 Playlist File unchanged` 후 stall(시뮬레이터 리플레이 실측).

### 1-8. 증상 4: 설정 화면 겹침

`setupModeCards`는 카드를 앞 카드 아래에 이어 붙이고, `setupQualityRow`는 행을 `fixedCard.bottomAnchor`에 붙였다. 네이티브 카드(3번째)도 고정 카드 아래에 붙으므로 **두 뷰가 같은 y에서 시작**하고, 나중에 추가된 행의 버튼(높이 60)이 네이티브 카드의 제목·설명을 덮었다(수정 전 스크린샷에서 "SOOP 미디어 서버에서 원본…" 위에 1080p 버튼이 겹침). 이전 사이클(2026-10-09)이 2카드 구조에서 행을 고정 카드 아래에 둔 뒤 네이티브 사이클이 3번째 카드를 반복문에 추가하면서 생겼다.

## 3. 구현

### 3-1. `TSMuxer.swift`

| 항목 | 변경 |
|------|------|
| cts | `* 9 / 10_000` → `* 9 / 1000` |
| PTS 접두 | PTS+DTS일 때 PTS `0x31`(`0011`), PTS만일 때 `0x21` 유지, DTS `0x11` |
| 원점 | `1_000_000`(0.1초) → `10_000_000`(1초, 주석·참조 구현과 일치) |
| 세그 조립 | PES를 즉시 TS로 쓰지 않고 `pendingPES`(비디오=dts, 오디오=pts)에 모은다. IDR에서 경계(`cuts`)만 기록하고, **경계 이후 시각의 오디오가 도착하면**(오디오는 시각순) 또는 영상이 경계를 2초 지나면 그 세그를 확정. 확정 시 `[start, end)` PES를 시각순 정렬해 TS로 패킷화(CC는 출력 순서대로) |
| 오디오 폐기 | 가장 오래된 미확정 세그보다 이른 오디오만(= 첫 영상 이전) |
| EXTINF | 다음 경계 − 이번 경계(실제 길이). 예전엔 마지막 프레임만큼 짧았다 |
| 오디오 PCR | 오디오 PES 첫 패킷은 random_access만(PCR은 PCR_PID인 비디오에만). 예전엔 PCR=0을 실었다 |
| 송출 재시작 | 시퀀스가 재전송 범위(영상 1000·오디오 100)를 넘어 역행하거나 dts가 원점보다 이르면 → 남은 내용 내보내고 원점·SPS/PPS·시퀀스·시각 상태 초기화, 다음 세그에 `discontinuity` 표시 |

### 3-2. `LocalHLSServer.swift`

- 세그 보관: `sequence − maxKept` 세그를 지운다(최근 12개 유지, 노출 6개).
- `#EXT-X-DISCONTINUITY`(재시작 직후 세그 앞) + 창에서 밀려난 수만큼 `#EXT-X-DISCONTINUITY-SEQUENCE`(RFC 8216 4.3.3.3).
- TARGETDURATION = EXTINF **반올림** 최댓값(RFC 8216 4.3.3.1). 실제 길이 EXTINF(2.002초 등)에서 올림이면 2→3으로 라이브 중 바뀌기 때문.

### 3-3. `SOOPNativeReceiver.swift`

keep-alive 타이머를 0.25초 틱으로 돌려 **4초 경과 또는 (0.4초 무수신 && 직전 keep-alive 후 1초 경과)** 시 전송. 첫 미디어 전(nextFrame=0)에는 보내지 않음(참조 구현과 동일 — 프레임 0 시크 방지).

### 3-4. `PlayerViewController.swift`

- `recoverFromNativeFailure`: 실패한 세션이 화면에 드러났었고 재연결 3회 미만이면 플레이어 정리 → 프리롤 "원본 다시 연결 중…" → 네이티브 재시작. 아니면 `fallbackToCDN`. 재연결이 재생 전에 다시 실패하면 CDN.
- 수신기 실패(`onFallback`)·루프백 `.failed`·루프백 재생 중 실패(`AVPlayerItemFailedToPlayToEndTime`) 세 경로 모두 이 함수로. 재생 중 실패는 수신기도 멈춘다.
- `fallbackToCDN`: 남은 플레이어를 `tearDownAVPlayer()`로 정리하고 프리롤을 다시 띄운 뒤 CDN 시작.
- `playLoopbackHLS`: `didRevealPlayer = false`(CDN 경로와 동일).

### 3-5. `SettingsViewController.swift`

반복문에서 `.fixed` 카드 다음에 '고정할 화질' 행을 끼우고 `previous = qualityRow`로 이어 네이티브 카드가 행 아래에 오게 함. `setupQualityRow`는 선택 핸들러만 남김.
