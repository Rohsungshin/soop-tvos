### 1-1. 증상 재현 — 카드가 비어 보인다

시뮬레이터에서 설정 탭(임시로 초기 탭을 설정으로 지정한 확인용 빌드)을 열고 스크린샷을 채취했다.

- 비전 판독(2회, 서로 다른 크롭·강조): **두 카드 모두 "내부에 텍스트가 없는 빈 회색 상자"**
- 픽셀 스캔(정량): 카드1 내부 영역(y 393–507)에서 밝기>90인 텍스트 후보 픽셀을 검색 → **카드 왼쪽 가장자리 포커스 링(x 320–336)뿐, 본문에는 0개**
- 같은 화면에서 '설정' 제목·'영상 플레이 방식' 부제·하단 화질 버튼은 정상적으로 식별됨 → 앱 전체가 아니라 **카드 내부만** 안 그려지는 상태

### 1-2. 원인 — system 버튼의 자체 배경

`SettingsModeCard`(2026-10-05 신규 파일)의 구조:

```swift
private let button = UIButton(type: .system)   // ← 포커스·선택을 받는 오버레이
…
addSubview(button)                              // 카드 전체를 덮는 제약
```

- 카드 자체(`UIView`)의 배경 위에 제목·설명·체크아이콘을 올리고, 그 위에 **카드 전체를 덮는 투명한 system 버튼**을 포커스·탭용으로 얹는 구조였다.
- tvOS의 `UIButton(type: .system)`은 **자체 배경(크롬)을 그린다.** iOS와 달리 tvOS 버튼은 기본적으로 불투명한 둥근 배경을 가지며, 카드를 통째로 덮는 제약(상하좌우 전부 카드 경계에 고정)과 만나면 **버튼 배경이 카드 배경을 대체해 아래 라벨들을 전부 가린다.**
- 2026-10-05 사이클이 카드 버튼을 0×0에서 "카드 전체 덮기"로 고치면서(포커스는 해결) 이번엔 버튼 크롬이 내용을 가리는 결함으로 바뀐 것이다. 같은 제약을 쓰는 `SettingsQualityRow`의 화질 버튼들은 버튼 자체가 콘텐츠(타이틀)라 문제가 없었다.

### 1-3. "2번 항목 = 1080p" 기대의 출처와 사실

사용자 발언 "2번 항목 선택시 cdn을 통해 스트리밍 하지 않기 때문에 vpn 접근하지 않아도 1080 해상도를 지원해줄 것 같은데"는 **구 설정 탭의 두 번째 카드 '네이티브 원본 (1080p 직접 수신)'**을 가리킨다(그 카드의 설명 문구와 정확히 일치). TV에 아직 그 빌드가 남아 있어 실제로 그 카드가 보이고 있다(§1-4).

사실 관계:

| 항목 | 사실 | 근거 |
|------|------|------|
| 국내에서 1080p가 나오는가 | 그 경로(내부 캐시 서버 직접 수신)에서는 **예** — 1080p60·1440p60까지 실측 | `20261003` §1-2 실측 표 |
| VPN이 필요한가 | 아니오 — 지역 위조 없이 국내 익명으로도 수신됨 | 〃 |
| 그러면 쓸 수 있는가 | **아니오.** 시청자 인증이 없는 내부 서버에 비공식 프로토콜 클라이언트로 접속 — 접근 통제가 서버가 아니라 앱 코드에만 존재. 하네스가 `Third-Party Attack`으로 구현을 거부 | `20261003` §1-5·§1-7 |
| 사용자의 기존 결정 | 2026-10-05, 분석 보고 후 **"화질 고정 선택으로 교체"를 직접 선택** — 구 카드는 공개 경로(자동/고정 화질)로 교체됨 | `20261005` §0·§1 |
| 현재 상태 | 현재 작업 트리의 설정 탭에는 네이티브 카드가 **없다**(자동/고정 화질 2개). VPN 이슈와 무관하게 그 경로 자체가 중단된 것 | `SettingsViewController.swift` |

즉 "VPN 없이 1080p"는 그 경로의 실제 성능이 맞지만, 그 경로는 정책·승인 문제로 **이미 폐기**됐고 사용자도 대안을 선택한 상태다. 이번 요청은 새 정보가 아니라 **TV에 구 빌드가 남아 있어 생긴 기대**다.

### 1-4. 왜 TV에 구 설정 탭이 남아 있나 — 10-05 사이클의 중단

- 2026-10-05 낮: fixed-resolution 빌드를 워처가 TV가 비는 창을 기다려 설치(`10:58:50 INSTALL OK`, 컨테이너 `C0CBAB4C…`). 이 빌드엔 설정 탭이 아직 없다(같은 날 저녁에 추가됨).
- 2026-10-05 저녁 세션: 설정 탭을 자동/고정 화질로 구현·빌드 성공(`build/…22:06`) → **사용량 한도로 세션 사망, 설치 단계 미수행**(세션 로그 마지막: "You've hit your org's monthly spend limit").
- 그 이후 이 프로젝트에 설치 명령 실행 흔적 없음(세션 로그·시스템 로그 모두 0건).
- 따라서 TV는 **네이티브 카드가 있는 구 설정 탭**(정확히는 10-05 낮 빌드 = fixed-resolution + 구 설정 탭이 아니라, 그 이전 상태)을 보고 있다. 참고: 낮 빌드엔 설정 탭 자체가 없으므로 사용자가 본 "2번 항목"은 **저녁에 포팅되기 전 원본의 카드**이며, 그 원본은 네이티브/표준 카드 구성이었다(`20261005` §1).

### 1-5. 이번 수정의 전제 확인

- 카드 결함은 현재 작업 트리 코드에 그대로 있었다(§1-1 재현) — 10-05 저녁 빌드도 같은 결함을 품고 있으므로, 설치만 했다면 "빈 카드"가 TV에 그대로 나갔을 것이다.
- 화질 고정·자동 로직(플레이어 쪽)은 10-05 저녁 사이클에서 어드버설 리뷰까지 통과한 상태로, 이번에는 건드리지 않는다.

## 2. 기획

### 2-1. 카드 노출 수정

- **목표**: 카드의 제목·설명·체크가 항상 보이고, 리모컨 포커스·선택도 그대로 동작.
- **설계**: 오버레이 버튼을 `UIButton(type: .custom)`(배경 크롬 없음)으로 바꾸고 `backgroundColor = .clear`를 명시, 뷰 계층에서 **맨 아래(`insertSubview(button, at: 0)`)**로 내린다. 레이블이 버튼 위에 있으면 히트 테스트는 여전히 버튼이 받을 수 없으므로 (UIKit은 위→아래 순서로 히트 테스트), 라벨들의 `isUserInteractionEnabled`는 기본값 `false`(UILabel 기본값)라 문제없다. 포커스는 버튼이 받는다(라벨은 포커스 불가).
- **하지 않는 것**: 카드를 `UIControl`로 만들거나 focus 엔진을 손보는 재구조화 — 결함의 최소 수정이 3줄이므로.

### 2-2. 1080p 기대 정정

- **목표**: 사용자가 설정 탭에서 화질 상한을 오해하지 않게 한다.
- **설계**: 화질 행의 안내문에 사실을 명시한다 — "국내 네트워크에서 SOOP 공개 스트리밍은 보통 540p·360p만 제공하므로 1080p·720p를 골라도 그 아래 최고 화질(보통 540p)로 고정됩니다". `numberOfLines` 2→3.
- **하지 않는 것**: 네이티브 경로 부활(§1-3), 화질 버튼에서 1080p/720p 제거(해외 판정 세션에선 실제로 존재하는 등급이므로 유지).

### 2-3. 검증 계획

1. 시뮬레이터 빌드 경고 0
2. 수정 빌드 설정 탭 스크린샷 → 카드 라벨·체크 식별(비전 판독 + 픽셀 스캔)
3. 실기기 서명 빌드 성공 → TV 설치
