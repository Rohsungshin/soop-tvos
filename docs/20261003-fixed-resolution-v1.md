### 1-1. 참조 저장소가 1080p를 얻는 방법

[PERISU21/SOOPTV-1080p](https://github.com/PERISU21/SOOPTV-1080p) 0.7.6은 Python 수신기 + 로컬 HLS 서버 + Brave 확장 구조다.
핵심은 **공급원**이 우리 앱과 다르다는 점이다.

| | 우리 앱 (현재) | 참조 저장소 |
|---|---|---|
| 경로 | 공개 HLS CDN (`player_live_api` → `broad_stream_assign` → master playlist) | SOOP **내부 미디어 캐시 서버**에 비공식 TCP 클라이언트로 직접 접속 |
| 인증 | 로그인 쿠키 + AID 토큰 | **없음** (쿠키·토큰·서명을 싣지 않는다) |
| 변환 | 없음 (AVPlayer가 HLS를 그대로 재생) | 원본 H.264/AAC를 **트랜스코딩 없이** 재포장 → ffmpeg로 로컬 HLS → hls.js |
| 국내 상한 | 540p | **원본 그대로** |

참조 저자는 패킷 구조의 출처를 *"user's Android capture, corroborated with SOOP's public ALS parser"*라고 적어 두었다
(`soop_media.py:3`). 즉 공식 문서가 없는 내부 프로토콜을 앱 트래픽 캡처로 알아낸 것이다.

**지역·CDN·DNS·쿠키 조작은 하나도 쓰지 않는다.** 해외 CDN 지정도, `AbroadChk` 위조도 없다.
그래서 [이전 사이클](20260930-quality-selection-v1.md) §1-2가 금지한 세 가지에 **문자 그대로는 해당하지 않는다.**
다만 그 금지의 **취지**("SOOP이 국내 고화질을 agent·공식 앱으로 제한한 정책을 우회")에는 그대로 걸린다. 수단이 쿠키에서 내부 프로토콜로 바뀌었을 뿐이고, 우회 강도는 더 세다.

### 1-2. 실측 — 기술적 전제는 성립한다

국내 IP·익명으로 공개 방송 7개를 측정했다(2026-10-03 20:05~20:27).

| 방송(원본) | 앱의 HLS master | 캐시 경로 (원본 요청) |
|---|---|---|
| 1920x1080@60, 8Mbps | `hd` 960x540 · `sd` 640x360 **2개뿐** | **1920x1080@60** 8004kbps High@L4.2 |
| 1280x720@30 | 같음 (540p·360p) | **1280x720@30** Baseline@L3.1 |
| 2560x1440@60 | — | **2560x1440@60** 15953kbps High@L5.1 |
| 576x1024 (세로) | — | **576x1024** (세로 유지) |
| 1024x576 | — | **1024x576** |

- 즉 **국내 판정 환경에서도 캐시 경로는 원본을 그대로 준다.** 이전 사이클이 "국내는 540p가 상한"이라고 결론낸 것은 **HLS 경로 한정**이며, 이 경로에서는 성립하지 않는다.
- 지연도 유리하다: 캐시 경로 원본은 수신 시각 − 패킷의 벽시계값 중앙값 **0.009~0.010초**, HLS는 세그먼트가 내용 끝 기준 1.10~1.13초 뒤에야 재생목록에 뜨고 12초 창을 유지한다.
- 저화질(540p·360p) 요청은 서버가 트랜스코딩하므로 약 0.35초가 더 붙는다.
- 이 경로에서는 `VIEWPRESET`의 이름(sd/hd/hd4k/original)이 실제 전달 해상도와 **일치**했다(13개 성공 세션 전부). HLS 경로에서 거짓 광고였던 것과 다르다.

### 1-3. 화질은 유료가 아니라 "업로드 제공"과 교환된다

- SOOP 공식 입장(MTN 2023-12-12): *"720p 이상 고화질로 콘텐츠를 시청하길 원하는 경우, 이용자의 동의를 받고 고화질 스트리머를 설치해 그리드 기술을 사용"*, *"일반 화질 콘텐츠는 고화질 스트리머를 설치하지 않고도 자유롭게 시청 가능"*. 그 기술이 망 사용료를 900억 → 150억원대로 낮췄다고 밝혔다.
- 퀵뷰·구독 혜택 목록에 화질은 **없다**. 즉 고화질의 대가는 돈이 아니라 **P2P 중계 참여**다.
- 따라서 이 경로로 고화질만 받는 구조는 **업로드는 돌려주지 않으면서 수신만 하는** 형태가 된다. 기술적 제약이 아니라 사용자가 알고 판단해야 할 사실이다.
- 역으로, 앱이 P2P 중계를 구현하는 것은 검토 대상이 아니다 — 사용자 업로드 대역을 쓰고 외부 수신 연결을 여는 일이라 보안 면적이 커진다.

### 1-4. tvOS 재포장 실험 — 경로는 만들 수 있다

tvOS에는 ffmpeg가 없으므로 Swift로 직접 재포장해야 한다. 합성 소재로 MPEG-TS 먹서를 만들어 AVPlayer의 요구 조건을 실측했다
(macOS + tvOS 26.5 시뮬레이터, 모두 무음).

| 조건 | 결과 | 비고 |
|---|---|---|
| 모두 갖춘 대조군 | **재생** (startup 0.070초, stall 0, 1920x1080) | |
| **AUD(NAL 9) 없음** | **실패** — `readyToPlay`에 끝내 도달하지 못함 | **SOOP 스트림에는 AUD가 0개**다 → 먹서가 반드시 삽입해야 한다 |
| SPS/PPS를 처음에만 | **실패** | SOOP은 모든 IDR에 동반(100%) → 그대로 쓰면 됨 |
| PAT/PMT를 첫 세그먼트에만 | **실패**(라이브 중간 합류 시) | 매 세그먼트에 넣어야 한다 |
| PCR 없음 / 세그먼트당 1회 | **둘 다 재생** | PCR은 필수가 아니다 |
| 재생목록 1개로 시작 / 3개로 시작 | 1개 → stall 1회, 3개 → **stall 0** | 3세그먼트 확보 후 붙인다 |
| 중간 해상도 변경 | `EXT-X-DISCONTINUITY` 유무와 무관하게 전환됨 | |

**구조 결정 — 루프백 HTTP 리스너는 피할 수 없다.**

| 방식 | 결과 |
|---|---|
| `AVAssetResourceLoaderDelegate`로 **세그먼트까지** 메모리에서 공급 | **실패** — `CoreMediaErrorDomain -12881 "custom url not redirect"` (macOS·tvOS 동일) |
| 리소스 로더로 **플레이리스트만**, 세그먼트는 루프백 HTTP | 재생 (readyToPlay 0.110초) |
| 리소스 로더가 http로 리다이렉트 | 재생 (readyToPlay 0.115초) |

즉 공격면이 0인 "리스너 없는" 설계는 불가능하고, `NWListener`를 써야 한다.
그런데 `NWListener`는 기본값과 `acceptLocalOnly = true` **둘 다 `*:port`(전 인터페이스)에 바인드**되고,
`requiredInterfaceType = .loopback`(또는 `requiredLocalEndpoint = 127.0.0.1`)을 줘야만 127.0.0.1에 묶인다(실측).
tvOS에는 Local Network 권한 보호가 아예 없어(Apple TN3179 표: tvOS "no") OS가 막아 주지 않는다.

### 1-5. 접근 통제 — 중단의 첫 번째 이유

캐시 경로에는 시청자 권한을 증명할 수단이 없다. 이것은 "서버가 권한을 확인하지 않는다"는 뜻이기도 하다.

- 참조 구현이 19+·비번방을 거르는 것은 **자기 코드 안의 검사 두 줄**뿐이다(`soop_player.py:54-57`, `RESULT!=1`과 `BPWD=='Y'`).
- 우리 앱의 권한 판정은 전부 `SOOPAPIClient._fetchStreamInfo`에 있다(`SOOPAPIClient.swift:837-947`). 그런데 **로그인 세션에서는 19+ 방송도 `RESULT=1`** 이라(이전 사이클 [19+·비번방 문서](20260924-adult-and-password-rooms-v1.md)), `RESULT`만으로는 공개 방송을 가릴 수 없다. 현재 `StreamInfo`에는 `GRADE`·`BPWD`·구독 플래그가 **담기지 않는다**.
- 설계로 막을 수는 있다(공개 방송 한정, 기존 경로가 성공한 방송에만, 거부된 방송에 대한 폴백 금지 등 규칙 10개를 정리해 뒀다). 그러나 그 경우에도 **접근 통제가 서버가 아니라 앱 코드의 올바름에만 존재**하게 된다. 버그 하나가 곧 열람 제한 우회가 되는 구조를, 이 앱에 들이는 선택이 된다.

## 2. 기획

캐시 서버 경로(§1-7)는 하네스 거부로 진행할 수 없어, 사용자가 다음 두 가지를 선택했다(2026-10-05): **기존 결함 D1·D2 수정** + **공개 경로 안에서 화질 고정**.

### 2-1. D1 — 재생 중 끊김 감지

- **현재**: 앱이 실패를 아는 신호는 `AVPlayerItem.status == .failed`뿐이고, 이는 시작 실패에서만 온다. 재생 중 소스가 죽으면 `FailedToPlayToEndTime` 알림이 약 30초 뒤 오는데 앱은 이를 관찰하지 않아 화면이 멈춘 채 남는다(§1-6 D1).
- **개선**: 재생 중인 item마다 `.AVPlayerItemFailedToPlayToEndTime` 알림을 관찰한다. 알림이 오면 기존 `tryFallback(info:)`를 그대로 탄다 — 아직 폴백 전이면 대체 URL로 전환하고, 이미 폴백했으면 에러 카드를 띄운다. 관찰은 item 교체·`tearDownAVPlayer`·`deinit`에서 해제하고, 닫히는 중(`isBeingDismissed`)이거나 `avVC`가 없으면 아무것도 하지 않는다(code-audit가 지적한 IUO 비동기 크래시 방지).
- **범위 밖**: 방송이 정상 종료(ENDLIST)되면 `DidPlayToEndTime`이 오고 일시정지된다. 이 경우의 "방송이 종료되었습니다" 안내는 실제 SOOP에서 오탐 여부를 재야 해서 이번에 넣지 않는다(후속 후보).

### 2-2. D2 — 쿠키 누출

- **현재**: `startPlayback`·`swapPlayerURL`이 URL 호스트와 무관하게 sooplive 쿠키 전부를 Cookie 헤더에 싣는다(§1-6 D2).
- **개선**: 두 곳의 헤더 생성을 `playbackHeaders(for:)` 하나로 합친다. `Referer`·`Origin`·`User-Agent`는 CDN이 요구하므로 늘 싣되, **로그인 쿠키는 요청 호스트가 SOOP 도메인(`*.sooplive.com`/`*.sooplive.co.kr`)일 때만** 싣는다.
- **회귀 없음**: 현재 재생 URL(master·CDN)의 호스트는 모두 sooplive 서브도메인이다(실측: `live-pcweb-kr-cdn-z02.sooplive.com` 등). 따라서 SOOP 경로의 쿠키 전달은 지금과 **완전히 같고**, 비-SOOP 호스트(루프백 등)로의 누출만 사라진다. 아울러 전체 URL(토큰 포함)을 찍던 로그를 호스트만 찍도록 가린다.
- **D3(Secure 플래그 없음)**: 쿠키 주입 자체를 고치는 일이라 `SOOPAPIClient`의 넓은 변경이 필요하다. D2(호스트 기준 전송)로 평문·타 호스트 노출은 이미 막히므로 이번 범위에서는 D2로 충분하다. D3는 별도 후보로 남긴다.

### 2-3. 화질 고정 (공개 경로)

- **현재**: 수동으로 고른 화질을 `preferredMaximumResolution`(상한)으로 건다. 상한이라 망이 흔들려 내려가면 AVPlayer가 SOOP master에서 다시 오르지 않아([이전 사이클](20260930-quality-selection-v1.md) §2-7) 그 방송 내내 낮은 화질에 머문다. 진짜 "고정"이 아니다.
- **개선 방향**: 수동 N을 고르면 **그 등급 variant의 media playlist URL을 AVPlayer에 직접 넘긴다.** 렌디션이 하나뿐이라 ABR 전환 자체가 불가능해져 화질이 고정된다. 자동은 지금처럼 master를 넘겨 ABR을 유지한다.
- **필요한 것**: tvOS 17에는 `AVAssetVariant.url`이 없으므로 master playlist 본문을 `URLSession`으로 받아 직접 파싱해(CRLF, `EXT-X-STREAM-INF` + URI 줄) 등급→media URL 지도를 만든다. 메뉴 행도 이 지도에서 만든다(고정 재생 중인 단일 렌디션에는 `load(.variants)`가 0개라 메뉴가 '자동'만 남는 결함을 피한다).
- **구현 전 게이트(V0)**: "실제 공개 SOOP 방송에서 master를 파싱해 뽑은 variant media URL을 AVPlayer에 직접 넘기면 그 화질로 재생되는가"를 익명·음소거로 먼저 확인한다. 통과하면 구현하고, 실패하면 설계를 고친다(§3).
- 이 경로는 SOOP이 공개 HLS로 정상 제공하는 것을 받는 것이라 캐시 서버 경로(§1-7)의 정책·접근통제 문제가 없다.

작업 순서: D1·D2(작고 명확, D1은 화질 고정의 전제) → 화질 고정 게이트 → 화질 고정 구현.

## 3. 개선

전부 `PlayerViewController.swift` 한 파일 안에서 끝냈다. 새 파일·pbxproj·`SOOPAPIClient`·진입점 6곳은 바뀌지 않았다.

### 3-1. D2 — `playbackHeaders(for:)`

`startPlayback`·`swapPlayerURL`에 흩어져 있던 쿠키·헤더 생성을 정적 함수 하나로 합쳤다.

```swift
private static func playbackHeaders(for url: URL) -> [String: String] {
    var headers = [Referer / Origin / User-Agent]            // CDN이 요구 → 항상
    if host == "sooplive.com" || host.hasSuffix(".sooplive.com")
         || host == "sooplive.co.kr" || host.hasSuffix(".sooplive.co.kr") {
        headers["Cookie"] = sooplive 쿠키               // 로그인 쿠키는 SOOP 도메인에만
    }
    return headers
}
```

- SOOP 재생 URL(master·CDN)은 모두 `*.sooplive.com` 서브도메인(실측)이라 SOOP 경로 쿠키 전달은 이전과 동일 — 회귀 없음.
- 토큰이 든 전체 URL을 찍던 로그 두 곳(`startPlayback`·`swapPlayerURL`)을 호스트만 찍도록 가렸다.

### 3-2. D1 — 재생 중 끊김 감지

- `observePlaybackFailure(for:info:)` — 재생 중인 item마다 `.AVPlayerItemFailedToPlayToEndTime`를 관찰해 기존 `tryFallback(info:)`로 연결한다. 닫히는 중이거나 `avVC`가 nil이면 아무것도 하지 않는다(IUO 비동기 크래시 방지).
- `startPlayback`·`swapPlayerURL`에서 item마다 등록, `tearDownAVPlayer`·`deinit`·다음 item 등록 시 해제(`removePlaybackFailureObserver`).

### 3-3. 화질 고정

- **파서** `QualityLadder.renditions(fromPlaylist:baseURL:)` — master 본문에서 (해상도, media playlist 절대 URL)을 뽑는다. `Character.isNewline`으로 CRLF(SOOP)·LF를 모두 처리하고, URI 줄 끝의 콤마를 떼고, 상대 URI를 master 기준 절대 URL로 바꾼다(master의 aid 쿼리는 교체되고 variant 자신의 aid가 남는다). 순수 함수라 macOS 하니스로 검증한다(§4-1).
- **`loadRenditions(from:)`** — master 본문을 `URLSession`으로 받아 파싱하고, 등급→media URL 지도(`renditions`)와 메뉴 목록(`qualityOptions`)을 만든다. tvOS 17에는 `AVAssetVariant.url`이 없어 `load(.variants)` 대신 본문을 직접 파싱한다(URL이 있어야 고정할 수 있다). 방송당 한 번(`startPlayback`) 부른다.
- **고정 적용** `pinCurrentChoice` — 수동 N이면 N 등급 media URL로, 자동이면 master로 `swapPlayerURL(qualityReload:true)` 교체한다. 단일 렌디션이라 ABR 전환이 불가능해져 화질이 고정된다. 이미 그 URL이면 교체하지 않는다.
- **`selectQuality`** 는 이제 저장 후 `pinCurrentChoice`만 부른다. 예전의 "내리기=상한, 올리기=교체" 분기를 없앴다.
- **master 추적** `masterURL = info.timeShiftURL ?? info.viewURL` — TS(구독자) 방송은 viewURL이 TS라, 공개 master인 timeShiftURL을 파싱·고정 대상으로 쓴다. 수동 고정이면 TS 시도 없이 바로 그 등급 media URL로 간다.

**바뀐 동작(기록)**: 예전에는 내리기를 상한으로 걸어 끊김이 없었다. 고정은 화질을 바꿀 때마다 item을 교체하므로 **전환 시 짧은 검은 화면**(실측 로컬 ~0.1초, 인터넷 1~2초)이 생긴다. 저장된 수동 화질로 **시작**할 때도 master→고정 교체가 한 번 일어난다(프리롤 뒤 짧은 재转환). 요청한 "고정"의 비용이고, 대신 망이 흔들려도 화질이 떠내려가지 않는다.

**제거**: `QualityLadder.ceiling(forCap:)`(옛 selectByCap에서만 쓰였고 고정 방식에선 불필요), `loadQualityOptions`(→`loadRenditions`로 대체).

`QualityLadder` 구역(파서 포함)을 잘라 `import Foundation`/`CoreGraphics`만으로 단독 컴파일하고(하니스 불변식 유지) 38개 사례를 돌렸다 — **ALL PASS**.

| 묶음 | 확인 |
|------|------|
| 기존 규칙 회귀 | bucket(짧은 변)·label·options(2개 미만 []·1440 제외)·effective·target·choice(체크 재선택 시 저장값 유지)·cap·badgeLines·rowSubtitle |
| 파서 | CRLF(SOOP)·LF master, URI 줄 끝 콤마 제거, 상대 URI→절대(master의 aid 쿼리 교체, variant aid 유지), 불량 해상도·비 master·빈 입력 → 0개(크래시 없음) |

중요 버그를 여기서 잡았다: Swift에서 `"\r\n"`은 **단일 Character(grapheme)**라 `$0=="\n" || $0=="\r"`로는 CRLF가 나뉘지 않는다. SOOP master가 CRLF라 파서가 0개를 반환했고, `Character.isNewline`으로 고쳤다.

### 4-2. 고정 재생 (무음 macOS AVPlayer + 루프백 HLS)

무음(오디오 트랙 없음) 2-렌디션 사다리(960x540·640x360)와 SOOP 스타일 master(CRLF·URI 콤마)를 루프백으로 띄우고, **앱의 실제 파서**로 뽑은 media URL을 음소거 AVPlayer에 넘겼다.

| 모드 | 결과 |
|------|------|
| 파서로 540 고정 | `hd.m3u8` 선택 → presentationSize **960x540 전 구간 일정**, readyToPlay·playing(0 stall) |
| 파서로 360 고정 | `sd.m3u8` 선택 → **640x360 일정** |
| 자동(master) | ABR로 최고 960x540 재생(콤마 없는 master) |

→ media URL 직접 재생 = 단일 렌디션 = **ABR 전환 불가 = 고정**이 실측으로 성립했다.

### 4-3. D2 호스트 게이팅 (단독 유닛테스트)

`playbackHeaders`의 호스트 판정을 11개 케이스로 확인 — **ALL PASS**. SOOP 호스트(`live.sooplive.com`·CDN·`sooplive.co.kr`)는 쿠키 전달, 비-SOOP(`127.0.0.1`·`localhost`)과 **위장 도메인**(`evil-sooplive.com`·`sooplive.com.evil.com`·`notsooplive.co.kr`)은 쿠키 차단.

### 4-4. 빌드

시뮬레이터·실기기(arm64) 빌드 **성공, 코드 경고 0**. `xcodegen` 불필요(새 파일 없음).

### 4-5. 원격으로 검증 못한 것 (→ §8 수동)

- **실제 SOOP에서의 고정**: variant media URL(자체 aid 토큰)이 단독 재생되는지. 합성으로 메커니즘은 증명했고 SOOP master·variant 형식은 이전 사이클 실측([[20260930-quality-selection-v1]] §1-4)과 같지만, 실 토큰 재생은 기기에서 확인한다(T2~T5).
- **D1 실제 끊김**: 방송을 실제로 끊어 30초 뒤 에러 카드가 뜨는지(T7). 알림 발화는 이번 분석 code-audit에서 실측됐다.
- 리모컨 조작(버튼)은 원격 불가 — 사람이 확인한다.

## 8. 수동 테스트 체크리스트 (실기기에서 사람이 확인해야 하는 항목)

원격으로는 리모컨을 누를 수 없고, 앱 실행도 허락 없이는 하지 않는다. 설치된 빌드로 사람이 확인할 항목:

| ID | 절차 | 기대 결과 |
|----|------|----------|
| T1 | 방송 재생 → 트랜스포트 바 → ⚙(화질) | [음량↓][음량↑][음소거][⚙][자막][오디오]. ⚙에서 "화질" 팝업이 체크 행에 포커스를 두고 열린다 |
| T2 | 팝업 목록 | 국내면 [자동 ✓ '현재 540p', 540p, 360p]. 해외 판정이면 1080p·720p도 |
| T3 | 지금보다 **낮은** 화질 선택 | 짧은 검은 화면 뒤 그 화질로 바뀌고 **거기서 고정**된다. 배지가 그 화질 |
| T4 | 지금보다 **높은** 화질 선택 | 짧은 검은 화면 뒤 바뀐다. 포스터 프리롤·상단 메타·음량 HUD는 뜨지 않고, 플레이어가 닫히면 결함 |
| T5 | **고정 확인(핵심)**: 한 화질을 고르고 2~3분 시청 | 화질이 **저절로 떨어지지 않는다**(예전엔 망이 흔들리면 360p로 내려가 안 올라왔다). 망이 아주 나쁘면 끊길지언정 다른 화질로 바뀌지 않아야 한다 |
| T6 | 화질을 고른 뒤 다른 방송·다른 탭에서 재생 | 고른 화질로 **시작**한다(프리롤 뒤 한 번 짧게 전환될 수 있음). 그 화질이 없는 방송이면 그 이하 최고에 체크가 가고 저장 선호는 유지 |
| T7 | **D1**: 재생 중 공유기를 끄거나 방송이 끝날 때까지 둠 | 약 30초 뒤 "재생할 수 없습니다/재생이 중단되었습니다" 에러 카드(다시 시도/돌아가기). 예전엔 화면이 멈춘 채 남았다 |
| T8 | 구독자 타임머신(TS) 방송 | "안정 모드" 문구 없이 재생. 화질 메뉴·고정도 동작(TS 없이 바로 그 화질로) |
| T9 | 세로 방송 | 배지가 짧은 변 기준. 고정도 동작 |
| T10 | 비밀번호방·19+ 방 | 재입력·재로그인 없이 화질 전환. (고정 경로도 기존 인증 경로가 성공한 방송에만 쓴다) |
| T11 | 음량 낮추기·높이기·음소거 | 기존과 동일(HUD 포함) |
| T12 | 화질 팝업 열고 Menu 여러 번 | 한 단계씩 물러난다(팝업→스크러버→바 숨김→종료). 한 번에 두 단계 건너뛰면 결함 |

콘솔 로그로 확인(선택): `[Player] renditions: [540, 360] (parsed N)`, `[Player] URL host: … (cookies: on)`, 고정 전환 시 `quality reload`. **토큰이 든 전체 URL·쿠키 값은 더 이상 찍히지 않는다**(호스트/on·off만).
