### 1-1. SOOP이 실제로 내주는 화질 (실측)

앱과 같은 경로(`type=aid quality=master` → `broad_key={bno}-common-master-hls`, `return_type=lg_cdn_pc_web` → `view_url?aid=`)로

|------------|----------------------------|---------------|-------------|

| choi15778, wnnw, viichan6, mj0128, kus03125, dpcks007 (1920x1080) | 360 / 540 / 720 / 1080 / 자동 | `hd` 960x540 · `sd` 640x360 | 같음(측정한 방송) |

- 조사한 모든 방송에서 master는 **540p(`hd`)와 360p(`sd`)뿐**이었다(저비트레이트 방송은 360p 하나). 로그인과 익명이 같았다.
- 화질을 콕 집어 요청해도(`type=aid quality=hd4k|original`, `broad_key={bno}-common-hd4k|original-hls`) HTTP 200으로 응답하지만
  세그먼트는 **조용히 960x540**이었다(`ffprobe`, 세그먼트 이름도 `-common-hd-hls_`). `quality=auto`의 broad_key는 HTTP 400이다.
- `player_type=ott/atvapp/webm`, `return_type=lg_cdn_mobile_web / gs_cdn_pc_web`, `AbroadChk=OK` 쿠키 주입도 결과를 바꾸지 못했다.

  나오는 거짓 표기가 된다. 메뉴는 **재생 중인 master의 실제 variant**로 만들어야 한다.

### 1-2. 540p 상한의 원인과 실기기 1080p 관측

- **공식 웹 플레이어도 같다.** `LivePlayer.js`의 `WARNING_shouldConnectToAgentForHighQuality`는 국내 CDN에서 자동·원본·고화질을
  고르면 로컬 "고화질 스트리머"(agent) 연결을 요구하고, 연결이 없으면 `NORMAL`(hd, 540p)로 내린다. 예외는 해외 CDN
  (`aws_cf/azure_cdn/gcp_cdn`), 월드컵, `DH=1`, 미리보기다. 즉 agent 없는 국내 PC 웹의 상한이 540p다.
- **실기기는 1080p를 받은 적이 있다.** 2026-09-25 22:32 이전 사이클 실기기 셀프테스트 중, 그 시각 누군가 앱으로 보던 재생 로그가
  콘솔에 섞여 나왔다([이전 문서](20260924-adult-and-password-rooms-v1.md) §5-3). 같은 국내 경로 master(`live-pcweb-kr-cdn-z02…/auth_master_playlist.m3u8`)에서
  `presentationSize 1920x1080`이었다. 그 세션은 `abroadChk=OK`였고 TS 호스트가 `live-tm-sub-global-cdn-v02`였다(국내 판정이면 `-kr-cdn-z02`).
- **해석**: master의 variant 구성은 AID 발급 시점의 **서버 판정**(국내/해외)에 따라 달라진다. 교차 실험에서 variant 집합은 AID가
  정했고(예: 720p URL + 360p용 AID → 640x360), `AbroadChk=OK` 쿠키를 넣는 것만으로는 판정이 바뀌지 않았다(쿠키는 판정의 결과).
  GeoDNS 조회에서 SOOP 호스트는 한국 서브넷에 `-kr` 주소를, 미국 서브넷에 CloudFront를 돌려줬고 AAAA 레코드는 없었다.
  기기가 어떤 경로로 해외 판정을 받는지는 **확인하지 못했다**(기기 DNS 등, 원격 확인 불가).
- **원칙**: 앱은 서버가 master에 넣어 준 화질만 제공한다. 해외 CDN 지정, DNS·쿠키 조작처럼 **지역 판정을 우회하는 방법은
  쓰지 않는다.** SOOP이 국내 고화질을 agent·공식 앱으로 제한한 정책을 우회하는 일이기 때문이다. 이런 방법은 시험하지도 않았다.
  그래서 국내 판정 환경(이 Mac·시뮬레이터)의 메뉴는 "자동 / 540p / 360p"가 되고, 실기기처럼 1080p가 오는 환경에서는 1080p·720p가 나타난다.

### 1-3. `CHANNEL.TS`의 정체

- 코드 주석은 TS를 "1080p 우회용 인증 URL"로 설명하지만, 실제로는 **구독자용 타임머신 URL**이다
  (`LivePlayer.js`: `t.TS&&(this.szTimeShiftUrl=t.TS)`, `timeShiftType {QUICKVIEW:1, SUBSCRIBER:2, FREE:3}`, 서명 쿠키는 `private_auth.php`).
- `TS_TYPE=2`인 방송(본 방송 19개 중 6개)에만 있고, AVPlayer 헤더든 브라우저 헤더든 국내 401 / 기기 403이었다.
- 그래서 그런 방송은 매번 TS 실패 → `view_url+aid` 폴백(`swapPlayerURL`)으로 재생된다. 나머지 약 2/3은 처음부터 master로 재생된다.
  **두 경로 모두** 화질 선택이 적용돼야 한다.

### 1-4. master·variant 형식과 토큰

| 항목 | 실측 |
|------|------|
| master 형식 | CRLF 줄바꿈, URI 줄 끝에 `,`, 속성은 `NAME`(비표준, hd/sd)·`BANDWIDTH`·`RESOLUTION`뿐(CODECS·FRAME-RATE 없음) |
| variant URI | 상대경로 `auth_playlist.m3u8?aid=<variant 전용 토큰>` — master 토큰과 다르다. master 기준 해석이면 토큰이 자동으로 따라간다 |
| segment URI | 상대경로 `<WxH>/<bno>-common-<preset>-hls_<seq>_<hash>.TS`, 쿼리 없음 |
| CDN 검사 | `Referer: https://play.sooplive.com/…`만 본다(Cookie 불필요). 헤더 없이는 403 |
| 토큰 수명 | 같은 master·variant URL이 584초 뒤에도 200. 상한은 재지 않았다 |
| 선언 대역폭 | 선언값(hd 777,600 / sd 345,600)이 실제(hd 1.1~1.5Mbps / sd 약 0.9Mbps)보다 낮아 AVPlayer가 `-12318`(비치명)을 남긴다 |
| AVFoundation | 앱과 같은 헤더로 `load(.variants)` → 0.06초에 2개(960x540·777600, 640x360·345600). `NAME`은 노출되지 않는다 |

### 1-8. 분석 결론 — 기획의 전제

1. 화질 목록은 **재생 중인 item의 실제 variant**(`load(.variants)`)로 동적으로 만든다. 1080p/720p/540p/360p 중 있는 것 + 자동.
2. 라벨은 **짧은 변**(`min(w, h)`) 기준으로 매긴다. 메뉴와 화면 라벨이 같은 함수를 쓴다(세로 방송 오표기도 함께 해소).
3. 지역 판정 우회는 하지 않는다(§1-2).
4. 선택 적용은 `startPlayback`·`swapPlayerURL` **두 경로 모두**, 재시도 뒤에도 유지돼야 한다.
5. 열린 쟁점(기획에서 결정): 선택을 **상한**(끊김 없음, 느리면 더 낮아짐)으로 적용할지 **강제 고정**(교체 공백·끊김 위험·토큰 재발급 문제)으로 할지,
   "자동"의 상한(현재 1920x1080 → 제한 없음?), 선택 저장 범위, 쓸 수 없는 화질의 표시(숨김/비활성).

### 2-2. 채택안 — 재생 중 item의 해상도 상한만 바꾼다

- **적용 방식**: 사용자가 고른 화질을 `AVPlayerItem.preferredMaximumResolution`(해상도 **상한**)으로 건다. item 교체, URL·토큰 재발급,
  폴백 예산 소모, 포커스 이동이 없다. 그래서 전환 중 화면이 끊기지 않는다. 시뮬레이터 실측으로 올릴 때 약 0.4초, 내릴 때는 버퍼를 다 쓴 뒤 약 3초가 걸렸다.
- **상한 모양**: 한 변이 N×16/9인 **정사각형**이다(360→640², 540→960², 720→1280², 1080→1920²). AVFoundation은 가로·세로를 따로 비교하므로
  정사각형 하나로 가로·세로 방송 모두 "N 등급 이하"가 된다.
- **"자동"**: 1920×1920 상한(1080p 등급)이다. 가로 방송은 지금의 1920x1080 상한과 허용 variant가 **같아 회귀가 없고**, 세로 방송이
  540x960에 묶이던 문제만 풀린다. 1440p·4K variant는 지금처럼 제외한다. 요청이 1080p까지이고, 기기(A12)의 1440p·AV1 재생은 검증되지 않았다.
- **의미**: 수동 N은 "최대 N"이다. 망이 느리면 끊기는 대신 더 낮은 화질로 내려가고, 망이 회복되면 N까지 다시 올라간다.
  국내 판정 환경(자동/540p/360p)에서는 망이 정상이면 고정과 결과 화질이 같다. 한 방송의 최고 화질 행은 자동과 같은 상한이다.
- **목록**: item을 만든 직후 `load(.variants)`로 master의 실제 variant를 읽는다. 짧은 변 기준 등급 중 1080/720/540/360에 있는 것만 "자동" 아래에
  높은 순으로 둔다. 등급이 **2개 미만이면 행을 두지 않는다**(메뉴는 "자동"만).
- **기억**: UserDefaults `soop.player.quality`(Int, 0 = 자동)에 전역으로 저장한다. 음량(`soop.player.volume`)과 같은 방식이다.
  사용자가 메뉴에서 고를 때만 쓴다. 스왑·다시 시도·다음 방송은 item을 만들 때 이 값을 읽어 그대로 적용한다.
- **저장한 화질이 없는 방송**: 체크는 "저장값 이하 중 최고, 없으면 최저" 행에 둔다. 상한은 저장값 그대로 둬서 AVPlayer가 고르는 화질이 체크한
  행과 같다. **저장값은 덮어쓰지 않는다.** 1080p 선호가 540p 전용 방송 한 번으로 사라지지 않게 하기 위해서다.
- **표시**: 체크는 "선택", 우상단 배지는 "실제"다. 기존 해상도 라벨을 화질 배지로 바꾸고, 짧은 변 기준으로 표기한다.
  " 안정 모드 " 배지는 없앤다. 정확한 문구와 모양은 §3 디자인에서 정한다.
- **변경 범위**: `PlayerViewController.swift` 한 파일만 바꾼다. 순수 규칙(`enum QualityLadder`)은 파일 끝 `// MARK: - 화질 규칙` 구역에
  UIKit·AVFoundation 없이 둔다. 그래서 macOS 하니스로 규칙을 따로 검사할 수 있다. 새 파일·pbxproj·`SOOPAPIClient`·진입점 6곳은 바뀌지 않는다.
  기획 드라이런 결과는 +125/−31줄, tvOS 17 타깃 typecheck 진단 0, 규칙 하니스 30개 성질 사례 ALL PASS였다(상한을 가로 상자로 바꾼 변이는 FAIL 7).

### 2-5. 적대적 비평과 반영

최종안에 대한 비평 판정은 "needs-fixes"(중요 1, 사소 7)였다. 모두 반영했다.

|--------|------|------|

| 사소 | 상한이 `AVPlayer(playerItem:)` 뒤에 걸려 첫 variant 선택보다 늦을 수 있다 | item을 만든 직후, 플레이어에 붙이기 전에 건다(F2) |

### 2-6. 기본값으로 진행하고 확인받을 것

제 판단으로 기본값을 정하고 진행한다. 바꾸고 싶으시면 알려 주세요.

1. **수동 선택 = "최대 N"(상한)**. 끊김·공백이 없고, 망이 나쁠 때는 더 낮아진다. 망이 나빠도 화질을 유지하는 "강제 고정"은 전환마다 1~2초 검은 화면과
   끊김 위험이 있어 기각했다. 재검토 조건은 기기에서 "정상 망인데 선택 화질에 닿지 않음"이 관측되는 경우다.
2. **자동 = 1080p 등급 상한**. 제한 없음(SOOP 웹 AUTO)은 코드 한 줄 차이다.
3. **선택은 전역 기억**. 방송마다 자동으로 시작하는 쪽도 한 줄 차이다.
4. **국내 판정 환경의 메뉴는 "자동/540p/360p"**(저비트레이트 방송은 "자동"만). 720p·1080p는 서버가 줄 때만 나타난다(§1-2 원칙).
5. **실기기는 설치까지만** 한다. 실행과 `[Player] variants` 로그 확인은 허락해 주시는 시간에 한다.
6. 요청 밖이라 이번에 하지 않는 것: TS 순서 변경, 셀프테스트 결함 수정, 기존 로그의 토큰 일부 출력 정리(§6에서 판단).
7. (디자인에서 추가) 저장한 화질이 방송에 없을 때 배지에 "{저장값} 없음"을 쓰지 않고, 저장은 체크가 옮겨 갈 때만 한다(§3-7).
8. (검증에서 추가) Menu 처리 수정(§4-3): 기존 코드가 팝업·바를 닫으려던 Menu로 영상을 멈추거나 플레이어를 닫던 결함을 tvOS 표준(한 단계씩)으로 고쳤다.

### 3-3. 메뉴 행

- **행 제목(고정)**: "자동", "1080p", "720p", "540p", "360p". 만든 뒤 제목은 바꾸지 않는다(제목 제자리 변경은 측정되지 않았다).
- **순서·개수**: "자동"이 맨 위, 그 아래 재생 중 master에 있는 등급을 높은 순으로. 등급이 2개 미만이면 "자동" 한 행만.
  비활성·숨김·안내 행과 행 아이콘은 없다.
- **체크**: 늘 정확히 한 행. 저장값이 있는 행, 없으면 저장값 이하 중 최고(없으면 최저) 행, 행이 없으면 "자동".
  `.singleSelection`의 자동 이동에 기대지 않고 보관한 `UIAction`의 `state`를 직접 맞춘다(tvOS 17~25 대비).
- **부제**: 체크 행에만 "현재 {실제}". "자동"이면 실제를 아는 한 항상, 수동 행이면 실제가 다를 때만. 실제를 모르면(교체 직후) 비운다.
- **예시**: 국내 [자동 ✓ '현재 540p', 540p, 360p] / 해외 [자동 ✓ '현재 1080p', 1080p, 720p, 540p, 360p] /
  수동 미도달 [자동, 1080p, 720p ✓ '현재 540p', 540p, 360p] / 360p 단독 [자동 ✓ '현재 360p']
- **다시 고르기 = 복구**: SOOP은 같은 item에서 다시 오르지 않으므로(§2-7), 체크된 행이나 "자동"을 다시 고르면 목표와 실제를 비교해 낮으면 새 item으로 복구한다.
- **저장은 체크가 옮겨 갈 때만**: 체크된 행을 다시 고르는 복구는 저장값을 바꾸지 않는다. 그래서 1080p를 저장해 둔 채 국내 방송에서 대체된 540p를
  다시 골라도 1080p 선호가 남는다.

### 4-3. 검증 중 발견해 고친 결함 — Menu가 한 단계를 건너뛰거나 영상을 멈춤

- **발견(S13, XCUIRemote)**: 화질 팝업을 연 채 Menu를 누르면 팝업은 닫혔지만 **영상이 일시정지**됐다. 트랜스포트 바만 보일 때 누른 Menu는
  바를 닫는 대신 **플레이어를 종료**했다.
- **원인**: 기존 `pressesBegan`이 Menu를 누르는 순간 무조건 `backTapped()`(`pause()` + `dismiss`)로 보냈다. AVKit은 Menu를 누름 시작에는 흘려보내고
  나중에 취소로 소비한다. 팝업이 떠 있을 때의 `dismiss`는 PlayerViewController가 아니라 그 위에 뜬 팝업을 닫았고, `pause()`는 그대로 실행됐다.
  이 구조는 음량 사이클부터 있었지만 그때는 확인되지 않았다(음량 문서 §6 T9 미확인). 화질 메뉴 때문에 바를 쓰는 일이 늘면서 "화질을 고르고 Menu로
  바를 닫으려다 방송이 꺼지는" 함정이 됐다.
- **1차 수정(pressesEnded로 이동)**: 팝업·바 단계는 해결됐다. 그러나 아무것도 떠 있지 않을 때도 AVKit이 누름을 취소로 소비해 **종료가 되지 않았다**.
- **최종 수정**: AVKit 헤더(`AVPlayerViewController.h` 423–429)는 "플레이어가 다른 뷰에 끼워 넣어진 경우 델리게이트가 닫기를 구현해야 할 수 있다"고
  적는다. 이 앱이 그 경우다(자식 VC). 그래서 `playerViewControllerShouldDismiss`에서 `backTapped()`를 부르고 `false`를 돌려준다.
  AVKit이 팝업 → 버튼 줄 → 스크러버 → 바를 한 단계씩 닫고, 더 닫을 것이 없을 때 이 델리게이트로 요청한다.
  프리롤·에러 카드에서는 AVKit이 응답하지 않고 UIKit의 모달 닫기가 Menu를 처리한다. AVKit·UIKit이 모두 쓰지 않은 누름만
  `pressesEnded`에서 종료한다(tvOS 26.5에서는 관측되지 않은 대비 경로).
- **리뷰 반영**: UIKit 모달 닫기는 `backTapped()`를 거치지 않아 `pause()`가 빠졌다. TS 폴백 프리롤(이미 재생 중)에서 닫으면 닫히는 동안 소리가 날 수 있었다.
  어느 경로로 닫혀도 멈추도록 `viewWillDisappear`(`isBeingDismissed`)에서 멈춘다.
- **결과**: §5-5의 Menu 사례 S13·S13b·S13c·S13e·S13f·S13g(일시정지)·S13h(팝업 + 재생/일시정지)가 모두 기대대로다. 다만 시뮬레이터에서는
  XCUIRemote의 재생/일시정지 누름이 재생 상태를 바꾸지 못해, "팝업을 연 채 재생/일시정지"는 플레이어 유지와 화질 불변까지만 확인했다(§8 T16).
- **사용자 확인 사항**: 기획은 "S13이 실패하면 사용자에게 묻는다"고 적었다. 새벽이라 답을 기다리면 사이클이 멈춰, tvOS 표준 동작(한 단계씩 물러나기)을
  되찾는 결함 수정으로 판단해 먼저 적용했다. 되돌리기를 원하시면 F9만 빼면 된다.

### 4-4. 사용 방법 (사용자 관점)

1. 방송 재생 중 리모컨을 **아래로 스와이프**(또는 클릭)해 트랜스포트 바를 연다.
2. 위로 한 번 올라가 버튼 줄로 이동한 뒤, 오른쪽으로 옮겨 **톱니(화질)** 버튼에서 Select를 누른다.
3. 목록에서 **자동 / 1080p / 720p / 540p / 360p** 중 고른다. 목록에는 지금 방송이 실제로 주는 화질만 나온다.
   국내 판정 환경에서는 보통 "자동 / 540p / 360p"다.
4. 우상단 배지가 실제 화질을 보여 준다. 고른 화질에 아직 못 미치면 "540p / 720p 선택됨"처럼 두 줄로 알린다. 화질을 **내릴 때는 끊김 없이 몇 초 안에**,
   **올릴 때는 짧게 검은 화면이 보인 뒤 곧바로** 바뀐다.
5. 고른 화질은 다음 방송에도 이어진다. 그 방송에 없는 화질이면 그 이하 중 가장 높은 화질로 재생하되, 저장한 선호는 그대로 남는다.
6. 화질이 떨어진 채 올라오지 않으면 같은 화질이나 "자동"을 **다시 고르면** 복구된다.
7. Menu는 한 번에 한 단계씩 물러난다(팝업 → 버튼 줄에서 스크러버로 → 바 숨김 → 플레이어 종료).

### 5-8. 토큰 수명 (올리기 교체의 전제)

같은 master URL(wnnw, 익명)을 Referer만 붙여 다시 받았다: +0·+15·+30·+60분 HTTP 200(variant 2개), +90분 **504**.
그 사이 방송이 끝났다(`player_live_api` `RESULT 0`, 라이브 목록에 없음). 그래서 504는 방송 종료로 설명된다.
**방송이 이어지는 동안 최소 60분은 유효**했다. 그 이상은 측정하지 못했다(§5-9).

### 5-9. 원격 검증 불가 / 남은 위험

- **실기기(tvOS 26.6)의 렌더링과 조작**: 행 부제, 체크, 부제 있음↔없음 전환(행 높이 66↔86pt), 2줄 배지의 3m 가독성, VoiceOver가 부제를 읽는지 → §8.
- **720p·1080p 행**: 이 Mac과 시뮬레이터는 국내 판정이라 실제 SOOP으로는 540p/360p만 볼 수 있다. 720p·1080p는 합성 사다리(S1·S4)와 규칙 하니스로만 확인했다.
  실기기가 해외로 판정되면 나타난다(§1-2). 설치 후 실행 허락이 있으면 `[Player] variants` 로그로 확인한다.
- **일시정지 상태에서 Menu**: 드라이버로 일시정지를 건 S13g로 확인했다. 리모컨 재생/일시정지로 멈춘 경우와 "팝업 연 채 재생/일시정지"의 재생 토글은 기기에서 본다 → §8 T6·T16.
- **4:3 사다리**: 정사각형 상한은 16:9·9:16 사다리를 전제로 한다(SOOP 실측 전부 16:9). 4:3 사다리라면 한 등급 위까지 재생될 수 있다.
- **tvOS 17~25**: 시뮬레이터 런타임이 26.5뿐이다. 체크는 명시 동기화로 보장하지만, `playerViewControllerShouldDismiss` 호출 시점과 부제 렌더링은 확인하지 못했다.
- **60분이 넘는 시청 뒤 올리기**: 같은 URL로 교체하므로 토큰이 만료되면 기존 에러 카드가 뜬다(다시 시도는 발급 당시 토큰을 쓰는 기존 한계).
- **자동 모드의 자동 복구 없음**: 자동도 순간 하락 뒤 다시 오르지 않을 수 있다(기존 동작, §2-7). 복구는 다시 고르기뿐이다.

### 6-3. 푸시 전에 조치한 것 — 공개 저장소의 개인정보
