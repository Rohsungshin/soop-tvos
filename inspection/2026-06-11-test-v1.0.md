## T2. 탐색 탭 (I-1) — 14점

### T2-a. 실패 → 오류 뷰 표시 + SearchEntryCell 유지 (5점)

**시나리오**: `ExploreViewController.loadData()` → `.failure` → 오류 뷰

   - `popularCategories = []`, `popularBroadcasts = []`인 상태이므로 해당 섹션 rowCount = 0.
   - 단, `Section.search` 섹션: `numberOfRowsInSection(.search) = 1` 항상 반환 → **SearchEntryCell은 표시됨**.

**검토**: 기획서 §1-2는 "검색 진입 셀은 그대로 유지"라고 명시. 코드는 tableView를 숨기지 않아 셀은 존재하지만, 오류 뷰가 화면 중앙을 덮어 시각적으로는 가려진다. 그러나 포커스 엔진 관점에서 `preferredFocusEnvironments`가 errorView를 반환하므로 tvOS 리모컨으로 오류 뷰 → 재시도 버튼에 포커스가 맞춰지고, 방향키 아래로 이동 시 tableView의 SearchEntryCell에 도달 가능하다. 기획 취지("검색 진입 셀 접근 가능 유지")를 만족.

## T7. 안정성 — 5점

### T7-a. [weak self] 메모리 누수 (2점)

**검토 대상**: 모든 변경 클로저

- `HomeVC.showErrorState()`: `onRetry = { [weak self] in ... }` ✓
- `HomeVC.loadData()`: `fetchCategories { [weak self] result in ... }` ✓ (기존 패턴 유지)
- `HomeVC.loadPopularLive()`: `DispatchGroup.notify [weak self]` ✓ (기존)
- `ExploreVC.showErrorState()`: `onRetry = { [weak self] in ... }` ✓
- `MyVC.showErrorState(for:)`: `onRetry = { [weak self] in self?.loadFavorites() }` ✓
- `SearchVC.loadAllBroadcasts()`: `fetchCategories { [weak self]` + group.notify `self.` (guard let self 없이 직접 사용)

**상세 검토 — SearchViewController `group.notify`**:
```swift
group.notify(queue: .main) {
    self.allBroadcasts = combined
    self.hasLoadedAll = true
    ...
    if self.isReloading { ... self.runSearch(q) }
}
```
이 클로저는 `[weak self]` 없이 `self`를 강하게 캡처한다. 단, `loadAllBroadcasts` 콜백 내 `DispatchQueue.main.async { guard let self = self else { return }` 블록 안에서 `group.notify`가 중첩 호출되는 구조:

```swift
SOOPAPIClient.shared.fetchCategories { [weak self] result in
    DispatchQueue.main.async {
        guard let self = self else { return }
        // ... group 생성 및 notify 등록
        group.notify(queue: .main) {
            self.allBroadcasts = ...  // ← 여기서 self는 guard-let 바인딩된 non-optional self
```

`guard let self = self`로 바인딩된 `self`는 해당 `DispatchQueue.main.async` 클로저 내에서만 유효하며, `group.notify` 클로저는 그 **밖**에서 `self`를 캡처한다. 실제로는 `DispatchQueue.main.async` 클로저가 `self`를 캡처하고 그 안에서 `group.notify` 클로저가 정의되므로, notify 클로저는 `guard let self`로 바인딩된 변수를 캡처 — 이는 강한 참조지만 임시 바인딩이라 사이클은 아님. DispatchGroup이 완료되면 클로저가 해제된다. 실질적 메모리 누수 없음. 다만 VC가 해제된 후에도 `group.notify`가 실행될 수 있어 존재하지 않는 VC에 접근할 수 있는 구조다. 그러나 이는 기존 코드의 패턴과 동일하며, main queue에서 실행되므로 문제는 없다.

**판정**: PASS (2/2)

## 참고: 코드 경로 추적 중 발견한 참고사항 (FAIL 아님)

### 참고1. `SearchViewController.group.notify` 클로저의 약한 캡처 부재
`loadAllBroadcasts()` 내 `group.notify(queue: .main)` 블록이 `[weak self]`를 선언하지 않는다.
이는 VC가 해제된 후에도 notify가 실행될 수 있는 구조이나, main queue에서만 실행되고 실질적 사이클은 아니다. 기존 코드 전반의 동일 패턴이므로 이번 변경에서 새로 도입된 문제가 아니며, 현재 사용 흐름에서 실질적 위험은 없다. 차기 개선 사이클에서 `[weak self]` 명시를 고려할 수 있다.

### 참고2. `ExploreViewController.showErrorState()` — tableView 미숨김
HomeViewController와 달리 ExploreViewController는 오류 상태에서 `tableView.isHidden = true`를 하지 않는다.
이는 기획서 §1-2 "검색 진입 셀은 항상 표시 유지"를 구현하기 위한 의도적 차이다. 오류 뷰가 중앙에 겹쳐 표시되는 동안 테이블이 배경에 남아 있어 포커스 이동 경로가 복잡해질 수 있으나, `preferredFocusEnvironments`가 오류 뷰를 우선하므로 초기 포커스는 "다시 시도" 버튼에 올바르게 맞춰진다. 기획 명세 범위 내 구현.
